2026-09-11 추가 연결: 예금 3,413개·적금 3,952개, 입출금 36개를 연결했다. [추가 연결 근거](audit/추가연결_근거.md). 아래 이전 실행 수치는 당시 기록이며 최신 수치는 audit/remaining_summary.json과 test_results.json을 따른다.

## 핀셋이 고르는 기준

사용자가 일일이 금융상품의 조건을 찾는 대신, **가입할 수 있고, 돈이 필요한 시점에 맞으며, 무리 없이 유지할 수 있는 계획**을 비교한다. 금리만 높은 상품이 아니라 같은 예산으로 얻는 결과를 비교한다.

신규 DB는 읽기 전용 원본이다. 원본의 금리·문구·상품을 수정하지 않는다. 조건 해석과 계산 방법은 이 폴더의 규칙 파일에서 관리한다. `source_lock.json`에 등록한 해시가 다르면 실행을 멈추며, 변경된 DB를 자동으로 승인하지 않는다.

## 추천 순서

1. **목표와 돈을 나눈다.** 목표일, 목표금액, 현금, 월 여력, 비상금, 예정 지출을 확인한다. 예금/적금을 사용자가 먼저 고를 필요는 없다. 현금과 월 여력이 모두 있으면 혼합 계획을 만든다.
2. **무리한 계획을 막는다.** 비상금과 예정 지출을 먼저 분리한다. 수입이 불규칙하면 적은 달의 여력까지 낮춰 계산한다. 사용자는 이 금액으로 진행할지 확인해야 한다. 사업 운영자금·고금리 부채는 별도 확인으로 연결한다.
3. **가입할 수 있는 후보를 찾는다.** 금융권 선택, 가입 경로, 금액 한도, 기존 보유상품, 계좌 수, 특별 자격을 확인한다. 조건을 모르면 충족으로 처리하지 않는다.
4. **받을 수 있는 우대를 계산한다.** 조건은 충족·미충족·미확인으로 나눈다. 중복 불가 우대는 큰 것 하나만, 누적 가능한 우대는 합산하되 상품별 최대치를 지킨다. 공시 최고금리보다 높아지면 오류로 처리한다.
5. **같은 예산으로 계산한다.** 예금과 적금의 원금 투입 시점, 단리·복리 방식, 추가 비용을 반영한다. 예금+적금은 금융기관별 기존 잔액과 신규 금액을 합쳐 확인한다.
6. **확인된 계획을 비교한다.** 변동소득 사용자의 납입 유연성 → 목표 부족액 → 예상금액 순이다. 가입·자금 조건 위반을 금리 점수로 상쇄하지 않는다.
7. **추천 1개와 대안 2개를 설명한다.** 같은 상품의 기간만 다른 선택지로 3칸을 채우지 않는다. 적격 후보가 적으면 적은 수만 보여준다. 추가 답에 따라 순위가 달라질 수 있으면 결과를 잠정 비교로 표시한다.

‘납입 유연성 우선’은 서비스 정책이다. 실제 만기 유지 확률이나 학습된 행동 점수가 아니다. 자유적립이라고 납입을 줄여도 우대금리가 유지된다고 가정하지 않는다.

## 사용자 문항과 추가 질문

| 기본 질문 | 추천에 쓰는 이유 |
|---|---|
| 모으는 목적·목표금액·필요한 날짜 | 목표 자금과 사용 시점 구분 |
| 현금과 남겨둘 비상금 | 예금에 맡길 수 있는 금액 계산 |
| 예정된 지출의 금액·날짜 | 목표 자금에 중복 포함하지 않기 |
| 생활비를 뺀 월 저축 여력·소득 변동 | 고정 납입을 감당할 수 있는지 확인 |
| 중간에 돈을 꺼낼 가능성 | 별도 현금 확보 또는 인출 약관 확인 |
| 비교할 금융권·가입 방법 | 원치 않거나 이용할 수 없는 경로 제외 |
| 기존 상품·잔액 확인 여부 | 중복가입·합산한도 확인 |

금액은 자주 쓰는 금액 버튼과 직접 입력을 함께 제공한다. 구간으로 답한 경우 정확한 예상금액을 표시하기 전에 계산에 쓸 원 단위 금액을 확인한다.

나이·국적·거주, 급여 인정 방식, 카드실적, 재가입, 특정 자격 등은 관련 후보가 있을 때만 묻는다. 내부 규칙 키를 그대로 화면에 노출하지 않고 `questions.py`의 문구와 해당 상품 조건 설명을 붙인다. 아직 모든 상품별 문구가 완성된 것은 아니므로 UI 연결 전 문항 설명을 채워야 한다.

## 이자와 우대 처리

| 항목 | 처리 |
|---|---|
| 단리 예금 | 목돈 × 연이율 × 기간 |
| 단리 적금 | 각 월 납입금이 맡겨진 기간을 나눠 합산 |
| 월복리 | 각 납입금에 월별 복리를 적용해 합산 |
| 실제 일수 단리 | 납입일~만기일의 일수/365로 계산 |
| 금액별 금리 | 구간마다 나누어 적용하는 방식과 전체 잔액에 한 금리를 적용하는 방식을 구분 |
| 우대 중복 | 같은 배타 그룹은 최댓값만, 다른 그룹은 합산 |
| 추가 소비·연회비 | 입력한 추가 비용을 예상 이자에서 차감. 비용 미확인이면 잠정 후보 |
| 불명확한 복리 주기 | 월복리로 추정하지 않고 규칙 확인 대상으로 보존 |
| 쿠폰·추첨·향후 금리 | 확인되지 않은 수익을 확정금리에 합산하지 않음 |
| 세금 | 일반과세 15.4%를 사용하는 프로젝트 비교 가정. 절사·실제 세금 차이 가능 |

계산 모듈과 실제 상품 규칙 연결은 다르다. 월복리 계산기를 구현했다고 모든 복리 상품을 지원하는 것은 아니다. 현재 월복리 상품 1개의 12·24·36개월 선택지를 연결했다.

연결 사례인 주거래하나 월복리적금은 0.5%/0.9% 우대를 서로 더하지 않고 온라인 우대를 별도 합산한다. 분기 한도 때문에 일정한 월 납입은 100만원 이하로 제한한다. 기존 급여·연금 상품과 중복가입 조건도 확인한다. 조건은 [하나은행 상품 설명](https://www.kebhana.com/cont/mall/mall08/mall0801/mall080102/1455927_115157.jsp)으로 보충했고, 금리 숫자는 고정 DB 값을 유지했다.

## 장기 목표·혼합 계획

- 목표일 이전에 만기가 오는 기간을 비교한다. 가장 긴 기간을 무조건 고르지 않는다.
- 목표일까지 같은 월 금액을 모으는 계획을 기준으로 한다. 첫 상품 이후의 원금은 보관하고 재가입 이자는 0원으로 둔다. 장기 목표 전체의 최적 재가입 계획이라고 표시하지 않는다.
- 예금+적금은 두 후보의 조합을 비교한다. 같은 은행의 보호범위 등 공동 제약을 다시 확인한다.
- 조합 탐색은 좋은 조합부터 확인하되, 먼저 확인한 조합이 한도를 넘었다고 나머지를 버리지 않는다. 별도 전수 나열 결과와 탐색 순서를 대조하는 테스트가 있다.
- **한쪽 자금을 여러 금융기관에 나눠 가입하는 최적 배분은 아직 구현하지 않았다.** 전체 목돈 1개 예금 + 월 여력 1개 적금을 비교하는 범위다.

## 회복·완주 지원

`recovery.py`는 별도 현금 사용, 납입액 조정, 일부해지 확인, 중도해지 영향 확인의 흐름을 반환한다. 가능한 행동과 손실 계산 완료 여부는 구분한다.

일부해지 가능 횟수나 남겨야 할 잔액만 안다고 손실을 계산할 수는 없다. 가입 당시 약관·실제 납입일·해지일·우대 소멸 조건이 필요하다. 이 정보 없이 중도해지 이율을 만들어내지 않는다. 자금 부족 시 상품에서 인출해야 하는 사용자를 일반 만기 추천으로 통과시키지 않는다.

- 10,200개 점검을 통과했다. 수식·조건식·조합 탐색·예산 보존·업권·금리 상한·날짜·읽기 전용 차단을 포함한다.

## 현재 구현 범위와 남은 작업

`coverage.json`에 원본 12,542개 모두의 규칙 연결 상태가 있다. 연결되지 않은 상품을 삭제하거나 검증 통과로 바꾸지 않는다. 전체 DB에서 최고 결과임을 입증하지 않은 상태다.

- 새 기본 엔진은 월 납입·월 단리 상품의 기존 규칙을 재사용하고, 월복리 상품 1개를 추가했다. 기존 규칙의 모든 약관을 새로 전수 검수했다는 뜻은 아니다.
- 일별·주별 증액 적금은 기존 검증 모듈에 있으나 새 혼합 계획 엔진과 아직 연결하지 않았다.
- 입출금 금액구간 계산기는 구현했지만 197개 상품 전체를 개인별 추천으로 연결하지 않았다.
- 모든 미성년자·외국인·사업자 명의, 세제특례, 회전형·변동금리·선지급, 여러 계좌로 분할 가입, 실제 중도해지 손실까지 지원 완료한 것은 아니다.
- 수입·소비·보유계좌는 사용자 응답이다. 실제 금융 연동이나 가입·이체 실행은 없다.

이번 산출물은 **기준이 명확한 추천 엔진과 상품 규칙 확장 구조**다. ‘전체 상품·모든 사용자에 대한 최적 추천 완성’이라는 표현을 쓰지 않는다.

### 현재 납입 방식 정책
기존 income_pattern 기반 risk 우선은 대체되었다. income_pattern은 예산 계산에 사용하고 납입 선호는 contribution_preference로 받는다: fixed_ok / adjustable / compare / 미입력. flexible_only=True는 우선 유지한다. NEEDS_ANSWERS + contribution_choice이면 cards=[]이며 질문/방식별 비교안을 렌더링한다. compare는 동의가 아니고 비교를 펼치는 상태다. fixed_allowed는 최종 추천이 아닌 정액 포함 비교안, adjustable_only는 자유적립 비교안이다. 실제 추천은 선택 후 최대3개. preview에 상품별 기간을 표시하고 동일 납입 가정을 안내한다. 기존 전달 폴더는 별도 갱신 필요.


### 우대 행동 선택
bonus_intents는 bonus_intent.ACTIONS의 의미키→true/false/null 맵이다. facts의 가능 여부와 별개이며 true는 구체적 조건을 설명받고 실제 이행할 계획이라는 응답이다. 금액·거래등급 등 객관적 조건은 이 맵을 요구하지 않는다. 행동 선택 미입력은 미확인, 거절은 해당 행동 우대 제외. 가입조건 자체를 면제하지 않는다. bonus_intent.* 질문은 기존 조건 설명과 함께 제시하고 기본 동의를 채우지 않는다. 기존 기록의 우대 사례는 새 선택값을 명시해야 재현된다. 사실/기간/방식이 바뀌면 프런트에서 관련 의향을 재확인한다.
