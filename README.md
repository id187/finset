## 현재 사용자 흐름

시연 시작 버튼으로 목표·월 저축액을 정하고 자동이체 계획에 답하면 추천을 봅니다. 월 금액은 원 단위로 직접 입력하며 +1만·+3만·+5만 버튼을 반복해서 누를 수 있습니다. 목표가 없으면 일단 모으기로 시작합니다. 입력과 추천 결과는 메모리에서만 유지하며 새로 시작하거나 새로고침하면 초기화됩니다.

- 은행·저축은행·신협 중 비교할 금융기관을 선택하고 자유적립 상품만 볼 수 있습니다.
- 가입·기간·월 납입 범위를 적용한 뒤 같은 월 금액의 예상 세후 금액을 비교합니다.
- 모르는 우대는 금리에 더하지 않습니다. 순위를 바꿀 수 있는 추가 조건을 질문하고 답변을 바꾸면 즉시 재계산합니다.
- 하나은행 내맘적금의 계좌 자동이체 조건을 추가로 연결했습니다. 카카오·토스의 원문 파싱도 유지합니다.
- 상품별 원문, 기본금리, 적용 금리, 납입 방식과 한도, 상품·공시 링크를 결과에서 확인합니다.
- 목표가 부족하면 월 금액·기간 대안을 제공합니다. 상품 만기 이후의 재예치 이자는 가정하지 않습니다.
- 상품 찾기 메뉴는 현재 질문형 추천으로 연결됩니다. 완성 예시의 납입·회복·기록 화면은 별도로 유지합니다.

## 전체 DB 검사와 비교 범위

기존 원본과 파생 DB를 보존하고 `catalogue_db.py`가 별도 버전의 검증 DB를 만듭니다.

| 항목 | 검사 범위 |
|---|---:|
| 원본 상품 | 12,542개 |
| 금리 옵션 | 44,678개 |
| 원문 조건 조각 | 54,396개 |
| 기존 기간별 규칙 | 25,560개 |
| 입출금 규칙의 출처·금리 | 36개 |
| 현재 월 적금 비교 | 2,349개 상품 / 7,982개 기간 옵션 |

원본 DB와 기존 파생 DB의 SQLite 무결성·외래키를 검사하고 입력 파일의 SHA256을 전후 대조합니다. 모든 상품·금리 옵션의 연결, 수집 상태, JSON 형식, 금리 값·순서, 규칙의 원본 금리·기간 일치를 확인합니다. 기존 파생 DB의 원문·문장 위치·보존한 규칙을 원본과 다시 대조합니다.

전체 상품은 **적금 비교 가능 2,349개 / 조건·경로 검수 필요 3,330개 / 정보 조회 6,858개 / 수집 오류 5개**로 구분합니다. 전체 상품 검색에서 예금·적금·입출금, 기관·상품명, 검증 상태로 조회하고 원문과 검증 보고서를 볼 수 있습니다.

이 숫자는 전체 금융상품의 의미 해석 완료나 최신 판매 검증을 뜻하지 않습니다. 예금·입출금은 정보 조회 범위이며 현재 주 흐름은 매월 적금입니다. 추가 비용, 합산 한도, 복잡한 가입조건, 미해석 우대, 미지원 계산 방식과 비대면 경로 미연결 상품은 자동 추천에 넣지 않습니다. 코드K의 프로모션 코드 우대는 가정하지 않고 기본금리만 사용합니다.

## 데이터 기준

- 상품·금리는 **2026년 8월 수집 자료**이며 최신 금리가 아닙니다. 현재 판매 여부와 실제 가입 승인은 금융기관에서 확인합니다.
- 금융정보는 명시한 **가상 인물**입니다. 국내 거주 만 19세 내국인, 앱·웹 이용 가능, 모든 비교기관 기존 잔액 0원·보유 적금 없음, 별도 비상금 확보, 우선 검토할 대출 없음, 만기 유지, 토스 입출금통장 보유 상황을 사용합니다. 추가 금융기관의 계좌 조건은 자동으로 가정하지 않습니다.
- 현재 시연의 기관별 원리금 비교 한도는 1억원입니다. 이를 모든 업권에 대한 법률상 보호 판정으로 표현하지 않습니다.
- 실제 계좌 조회·로그인·가입·이체·다중 사용자 저장은 구현하지 않았습니다. 이전 완성 예시의 브라우저 기록은 유지하며 주 질문 흐름과 전체 상품 조회에서 쓰지 않습니다.
- GitHub Pages는 정적 웹입니다. 공개 상품·검증 결과·검수한 규칙을 JSON으로 배포해 브라우저에서 계산합니다. SQLite 원본과 파생 DB, 사용자 기록, 인증정보는 Git에 포함하지 않습니다.

## 검증과 실행

```powershell
npm ci
npm run test:model
npm run test:pages
npm run build:pages
npm run preview:pages
```

기존 원본 패키지가 `../mvp/핀셋_MVP_팀원전달`에 있을 때 전체 검사·기준 결과를 재생성합니다. 다른 위치는 `FINSET_DATA_DIR`로 지정합니다.

```powershell
python -X utf8 catalogue_db.py
python -X utf8 scripts/export-catalogue-parity.py
python -X utf8 -m unittest discover -s tests -v
npm run test:catalogue
node scripts/audit-catalogue.cjs
```

브라우저 검수는 기본 `http://127.0.0.1:4175/finset/`에서 실행하며 `FINSET_URL`로 변경합니다. Playwright 모듈 위치는 `PLAYWRIGHT_MODULE`로 지정할 수 있습니다.

- 1,525개 원본 Python Decimal 기준 계산으로 전체 공개 옵션의 금리·기간·계산 방식을 검증합니다.
- 기존 645개 추천, 110개 계산, 225개 우대 평가, 37개 회복 사례의 회귀 테스트를 유지합니다. 이전 3개 상품 자료는 회귀 기준이며 현재 추천 범위와 다릅니다.
- 실제 브라우저에서 입력·증액, 금융기관 필터, 우대 변경, 추가 질문, 목표 대안, 전체 검색·원문·오류 상품, 페이지 이동, 네트워크 오류 재시도, 기존 저장 데이터 보존을 확인합니다.
- `.github/workflows/pages.yml`이 main push 시 테스트·빌드 후 Pages에 배포합니다.

## 파일 구조

- `catalogue_db.py`: 원본 전체 검사, 별도 `app_data/catalogue_audit_v2_<입력·코드해시>.sqlite3` 생성, 공개 JSON 내보내기
- `condition_db.py`: 기존 `bonus_conditions_v1.sqlite3` 생성·조회. 원본은 불변
- `public/demo/full-catalogue.json`: 추천에 연결한 상품·옵션·원문·질문
- `public/demo/inventory.json`: 전체 상품 검색과 검증 상태
- `public/demo/audit-report.json`: 검사 범위·오류·제외 사유·해시
- `src/catalogue.ts`: 현재 브라우저 추천과 필요한 추가 질문
- `src/Inventory.tsx`: 전체 상품 검색·출처·검증 현황

기존 로컬 API 모드는 `./start.ps1`로 실행합니다. 원본 패키지의 DB·rules.json·liquid_rules.json은 재생성하거나 수정하지 않습니다.
